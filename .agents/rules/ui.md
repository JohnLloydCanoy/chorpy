# UI Rules

These rules are established to eliminate AI-generated visual clichés and enforce clean, high-contrast, accessible visual design standards. All AI agents and developers shall strictly abide by these rules.

1. **No Gradients**: Do not use dynamic gradients, linear gradients, radial gradients, or text gradient masks (`bg-clip-text text-transparent bg-gradient-to-r`) anywhere unless explicitly requested by the developer. Use only solid colors.
2. **Solid Colors Only**: Use only solid colors for all surfaces, backgrounds, borders, text, and controls. Always refer to the colors and design tokens established in the project documentation or existing project styles.
3. **No Neon Box Shadows or Glows**: Do not use neon box shadows, ambient glow halos under buttons, or radiant colored lighting effects on any element.
4. **No Heavy Glassmorphism**: Do not default to heavy glassmorphism (`backdrop-blur` + low-opacity white borders) as a substitute for visual hierarchy. Rely on clean 1px solid borders (`border-neutral-200` / `border-neutral-800`) and subtle, physically realistic neutral elevation.
5. **No "Dark Mode" Cliché**: Avoid dark backgrounds paired with indigo-to-purple gradients, dot grids, and large, blurred glowing orbs behind text. Use deep neutral grays (`#0f172a`, `#18181b`, `#111827`) with structured surface layering and subtle border contrast (10–15% opacity).
6. **No "Bento Box" Hero**: Avoid centered hero sections featuring a pill-shaped "New" badge, massive headline, light-grey subtitle, two buttons (primary + outline), and a masonry bento grid. Design directly for immediate utility, workflows, and real functional previews above the fold.
7. **No Card Overload (Card-ception)**: Do not wrap every piece of information inside a rounded card, and never nest cards inside cards with identical corner radii. Use typographic rhythm, dividing lines, clean whitespace, and list or table layouts.
8. **No Whisper-Thin Typography**: Avoid massive, ultra-thin, low-opacity headlines that fail accessibility contrast. Use strong, legible weights (`font-medium`, `font-semibold`, `font-bold`) and maintain high contrast.
9. **No "Hello [Name]" Dashboard**: Avoid boilerplate dashboard layouts featuring a greeting, a summary card, four horizontal metric blocks, and one large chart. Tailor dashboard layouts specifically to the product's actual function and operational workflows.
10. **No Flat Visual Hierarchy**: Avoid perfectly symmetrical, repetitive sections where every element carries equal visual weight. Establish clear primary, secondary, and tertiary focal points through deliberate sizing, weight, and visual contrast.
11. **No "Colored Square" Iconography**: Avoid generic monoline icons placed inside softly rounded, pastel-colored squares next to every feature description. Use meaningful icons without decorative square containers, or rely on clear typographic headings alone.
12. **No Inter/Roboto Monoculture**: Do not default exclusively to system sans-serifs (Inter, Roboto, SF Pro) for everything. Select intentional typographic pairings aligned with project branding and distinct stylistic hierarchy.
13. **No Gradient Hero H1**: Never apply `bg-clip-text text-transparent bg-gradient-to-r` to landing page headlines. Use solid, high-contrast headline colors with purposeful weight and typographic character.
14. **No Muted Gray Unreadability**: Never default secondary or body text to `text-gray-500` on white surfaces or `text-gray-400` in dark mode. Strictly enforce WCAG AA minimum 4.5:1 contrast ratios across all text.
15. **No Extreme Size Jumps**: Avoid pairing massive `text-7xl` or `text-8xl` headlines directly with tiny `text-sm` body copy. Use balanced, mathematical step-wise type scales (e.g., Major Second, Minor Third, Perfect Fourth) for smooth heading-to-body transitions.
16. **No Spaced-Out Eyebrows**: Avoid overusing `uppercase tracking-widest text-xs font-semibold` as a default tag or category label above every headline. Use natural case and standard typographic hierarchy.
17. **No Random Italicized Serifs**: Never force a single word in a sans-serif headline to be a serif italic to simulate an "editorial" feel. Maintain consistent font family in headlines; express emphasis through natural phrasing, weight, or color.
18. **No Infinite Line Lengths**: Avoid unconstrained paragraphs stretching across wide viewports with orphaned words. Constrain text blocks to 45–75 characters per line (`max-w-prose`, `max-w-xl`/`max-w-2xl`) and apply `text-wrap: balance` to headlines.
19. **No Emojis on Text**: Absolutely no emojis in headings, body text, buttons, or labels (e.g., `✨`, `🚀`, `🔥`, `💡`).
20. **No Feature Badges**: Do not use pill-shaped "New", "Beta", or "Feature" badges. Reserve badges strictly for functional status indicators (e.g., "Active", "Pending", "Failed").
21. **Always Reference Project Assets**: Always refer to the project's asset folder or related files for icons, logos, and imagery on each development instead of using generic placeholder URLs, stock links, or empty placeholder boxes.
22. **Interactive Component States**: Every interactive component must define clear default, hover, visible keyboard focus (`ring-2 ring-offset-2`), active, disabled (`opacity-50 pointer-events-none`), and explicit empty/error states.
23. **Functional Copywriting**: No marketing buzzwords ("supercharge", "unleash", "next-gen") and no Latin placeholder text (`Lorem ipsum`). Write plain, factual, actionable copy with realistic domain data.
24. **Subtle & Accessible Motion**: No gratuitous hover micro-animations (bounce transitions, pulsating buttons, scale-105). Keep transitions fast and functional (150–200ms, ease-out) and strictly respect `prefers-reduced-motion`.
