# UX Rules

These rules are established to eliminate lazy AI interaction anti-patterns and enforce robust, state-resilient, human-centered UX design. All AI agents and developers shall strictly abide by these rules.

1. **No "Happy Path" Bias**: Never design only for ideal, populated conditions. Every screen, view, and component must explicitly engineer and test all five core UI states: **Empty** (constructive explanation + primary CTA), **Loading** (geometry-matched skeleton avoiding Cumulative Layout Shift), **Error** (clear root cause diagnostic + retry mechanism), **Partial** (degraded, cached, or optimistic updates with automatic rollback), and **Populated**.
2. **No "Chatbot" Hammer**: Do not slap an AI chat input, copilot widget, or prompt box onto the screen as a lazy substitute for proper UX. Design purpose-built workflows, specialized inputs, structured tables/forms, and direct-manipulation tools tailored to the specific domain task.
3. **No "Modal Maze"**: Never default to pop-up modals for standard interactions (editing profiles, trivial confirmations, viewing details). Use URL-backed page routing for primary workflows, slide-over drawers for auxiliary inspection, and inline editing for atomic updates. Reserve modals strictly for high-impact, irreversible destructive confirmations. Never nest or stack modals.
4. **No Lifeless Microcopy**: Banned vague, robotic, passive button labels and error messages (e.g., "Submit", "Get Started", "Learn More", "An error occurred"). Author specific, outcome-driven microcopy that explains the exact result (e.g., "Start Analyzing Data", "Export 42 Records to CSV", "Save Billing Address").
5. **No Amnesia Accessibility**: Always use native semantic HTML (`<button>`, `<main>`, `<nav>`, `<form>`). Never use non-semantic clickable `<div>`s or `<span>`s. Maintain visible, high-contrast keyboard focus rings (`ring-2 ring-offset-2`), full keyboard navigation (Tab, Enter, Space, Escape, Arrows), explicit `aria-label`s on icon-only buttons, `aria-live` announcements for dynamic updates, and strict WCAG 2.1 AA compliance.
6. **No Statistical Navigation**: Do not generate boilerplate navigation menus based on generic internet tropes ("Dashboard", "Settings", "Profile" dropdowns). Architect an Information Architecture (IA) derived directly from core user workflows, domain entities, and frequency of use, with persistent breadcrumbs and unambiguous active-route indicators.
7. **No "Infinite Data" Dump**: Never render unbounded datasets directly to the DOM assuming users only have 5 items. Implement DOM virtualization for lists exceeding 100 items, explicit pagination with configurable page sizes, responsive multi-column sorting, debounced search (300–500ms), and multi-select batch controls.
8. **Surface Selection Discipline**: Match the container to the task complexity: Full Page Routes for primary deep-linkable workflows; Slide-Over Drawers for contextual inspection; Inline Editing for atomic field updates; and Modal Dialogs strictly for destructive confirmations or critical blocking gates.
9. **Modal Safety & Dismissal**: Modals containing uncommitted form inputs must not dismiss on backdrop clicks without confirmation to prevent accidental data loss. Always bind `Escape` to close non-destructive overlays and trap keyboard focus cleanly within open dialogs, restoring focus on close.
10. **Preserve User Input on Failure**: In form validation or mutation failures, never wipe user-entered data or reset input fields. Keep inputs intact, pair inline field validation errors directly beneath problematic fields (`aria-describedby`), and highlight actionable recovery steps.
11. **Optimistic Updates & Automatic Rollback**: Mutate the UI immediately upon user action for perceived speed. If the network mutation fails, automatically roll back to the prior state and present a clear error notification with an undo/retry option.
12. **Touch Targets & Ergonomics**: Ensure all interactive buttons, links, and form toggles maintain a minimum clickable target area of 44×44px (or 40×40px with appropriate spacing) for touch and motor accessibility.
13. **Deep Linking & State Synchronization**: Synchronize significant UI states (entity IDs, active tabs, search queries, filters, pagination index) with URL parameters to enable browser back-button navigation, bookmarking, and team sharing.
14. **Defensive Boundary Testing**: Every view, table, and list must be tested against edge-case data volumes: 0 records, 1 record, 10 records, 1,000+ records, and defensively truncate excessively long character strings with accessible tooltips (`truncate max-w-xs`).
