# Code Verification & Quality Assurance Rules

> **Purpose:** This rulebook defines the mandatory verification gates and "Definition of Done" that the agent must execute before declaring any code change, feature, or bug fix complete.

---

## 1. The "Definition of Done" Standard

A task is **NOT** complete simply because code was written. A task is only complete when:
1. All modified and created files pass static typechecking with **zero errors**.
2. Code follows the established architecture in `.agents/instructions.md`.
3. UI components adhere to the anti-slop standards in `5. ui-ux-standards.md`.
4. No existing functionality or working code was unintentionally broken or removed.
5. The agent explicitly reports the verification results to the developer.

---

## 2. Mandatory Verification Gates

The agent must execute these automated checks inside the `mobile/` directory:

### Gate 1: Strict TypeScript Typecheck (Non-Negotiable)
Before reporting any code task as done, run:
```bash
cd mobile && npx tsc --noEmit
```
* **Pass Criteria:** Process exits with code `0` and outputs zero errors.
* **Action on Error:** Fix all type mismatches, missing imports, or incorrect prop types immediately. Never suppress errors with `@ts-ignore` or `any` without explicit user permission.

### Gate 2: Linter & Syntax Check
```bash
cd mobile && npx expo lint
```
* **Pass Criteria:** No unresolved syntax errors, broken import paths, or unused variables.

### Gate 3: Dependency & Health Check (When Packages Change)
Whenever `package.json`, `app.json`, or native dependencies are touched:
```bash
cd mobile && npx expo-doctor
```
* **Pass Criteria:** Confirms all installed packages are 100% compatible with **Expo SDK 51**.

---

## 3. Database & Supabase Verification

Whenever modifying database schemas, functions, or queries:

* **Row Level Security (RLS) Gate:**
  * Every table in `database/` MUST have an `alter table public.<name> enable row level security;` statement.
  * Every policy must explicitly check `auth.uid()`, role, or circle membership.
* **Realtime Publication Check:**
  * Ensure any table requiring live mobile updates (`chores`, `devices`) is added to `supabase_realtime`:
    ```sql
    alter publication supabase_realtime add table public.<table_name>;
    ```
* **Trigger Safety:**
  * Custom functions (like `handle_new_user`) must specify `security definer` and handle null metadata gracefully.

---

## 4. Mobile Runtime & Edge-Case Checklist

Before declaring a screen or component ready:

1. **Empty / Null State Check:**
   * Does the screen handle `null`, `undefined`, or empty arrays (`[]`) without crashing or rendering a blank white void?
2. **Network Error Handling:**
   * Are Supabase API calls wrapped in `try / catch` blocks with user-facing error messages?
3. **Double-Submit Guard:**
   * Are buttons disabled and showing an `ActivityIndicator` while async actions are in-flight?
4. **Subscription Cleanup:**
   * Do `useEffect` hooks with Supabase Realtime listeners return an unsubscribe cleanup function?
     ```tsx
     return () => {
       subscription.unsubscribe();
     };
     ```
5. **Keyboard & Safe Area:**
   * Is the view protected against notch clipping (`SafeAreaView`) and keyboard obscuration (`KeyboardAvoidingView`)?

---

## 5. Regression & File Integrity Guardrails

* **Preserve Working Logic:** Never overwrite or delete existing working functions, comments, or types unless specifically instructed.
* **Scope Discipline:** Only edit files directly related to the user's prompt. Do not reformat or refactor unrelated files.
* **Git Cleanliness:** Check `git status --short` to ensure no unwanted scratch files or temporary build artifacts remain untracked.

---

## 6. Verification Report Format

When concluding a turn, the agent must provide a brief verification summary:
* ✅ **TypeScript Check:** `npx tsc --noEmit` passed (0 errors)
* ✅ **Architecture Check:** Services, theme tokens, and types aligned
* ✅ **Edge Cases:** Loading, empty, and error states handled
